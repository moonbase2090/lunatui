# lunatui-widgets

Widgets for lunatui (PRD §8). **v0.1.0** includes the Phase 4 set used by `examples/gallery.rs`.

## API

- [`Widget`](src/widget.rs): `render(&self, area, &mut RenderCx)` and `measure(&self, avail: Size) -> Size`.
- [`RenderCx`](src/render_cx.rs): grid, cluster table, and theme for token-aware drawing. Optional `color-profiles` feature adds `profile` for ANSI16/256 downsampling in `token`.
- `WidgetState` (normal, focused, disabled) sits behind `widget-state`, enabled by the default `pixel-pie-chart` feature. `barchart`, `bigtext`, `calendar`, `canvas`, `chart`, `combo-box`, `date-picker`, `notification-center`, `diff-view`, `markdown`, `nested-menu`, `popup`, `scroll-view`, `sparkline`, and `radio`, `form`, `accordion`, `hex-viewer`, `log-view`, `number-input`, `pie-chart`, `progress`, `search-box`, `slider`, `toast`, and `toggle` forward it. `line-gauge` reserves the same feature. `all-widgets` turns on every widget in one go; new widget features are added to it, so test setups do not need to list each widget.
- `KeyHintBar` is behind the `key-hints` feature. Construct it from the keymap active for the current screen or mode; it renders the first chord registered for each command.
- [`Size`](https://docs.rs/lunatui-core/latest/lunatui_core/struct.Size.html) lives in `lunatui-core` and is re-exported here.

## Widgets (v0.1.0)

`Block`, `Paragraph`, `List`, `Table`, `Tabs`, `Gauge`, `Scrollbar`, `Spinner`, `StatusBar`, `TextInput`, `Overlay`, `StatusDot`, and `Lightcycle`.

`KeyHintBar` is behind `key-hints` and draws the active keymap's shortcuts in registration order.

`BigText` is behind the `bigtext` feature. It draws large letters from an 8×8 bitmap, using full blocks (two columns per pixel), half blocks, quadrants, braille, sextants, or octants. Sextants pad one blank pixel row, and sextants and octants pack as quadrants until `subcell_glyphs` is set. It paints from theme tokens for the current `WidgetState` unless a style is set. Glyph bitmaps for digits, capitals, and `:.-%` use a modified 8×8 face with 2px strokes, derived from Press Start 2P by `CodeMan38` under OFL-1.1. The copyright and license notice is in [`assets/fonts/PressStart2P-OFL.txt`](assets/fonts/PressStart2P-OFL.txt). Select it with `BigTextFont::Modified8x8`, the default font. Other printable ASCII is a hollow box. The opt-in `FiveBySeven` clock font draws the digits `0`–`9` and `:`; unsupported non-control characters render a blank 5×7 glyph with the usual two-column inter-glyph gap, while control characters are skipped.

`Monthly` is behind the `calendar` feature. It draws one month in the same 21-column Sunday grid as ratatui, and can color the selected day from theme tokens.

`Chart` is behind the `chart` feature. It plots `Dataset`s of `(x, y)` points as scatter, line, or bar series with braille, half-block, dot, or block markers, draws `Axis` lines with bounds, labels, and titles, and lists named datasets in a legend that is hidden when it would take too much of the plot. Without styles, series cycle through theme tokens and the axes follow the `WidgetState`.

The default `pixel-chart` feature enables antialiased lines, circles, bars, and legend swatches through the runtime image presenter. Existing `Chart::new` calls use measured native pixels automatically; no image identity or revision is needed. `.pixels(false)` selects the original cell renderer, and the runtime's `RunOptions::pixels(false)` disables images globally. Reversed cell backgrounds also select cells because their displayed colors are swapped. The `pixel_chart` example keeps matched Braille and pixel views of Requests, Saturation CPU/memory, and latency scatter, plus native hourly bars, using the same data and layout as the preview scenes.

Missing metrics, unsupported graphics, unresolved colors, oversized workloads, rejected rasters, and unsupported series styles use cells. Normal and DIM colors are supported; per-series background colors or other text attributes use cells. Kitty preserves text above plot pixels. iTerm2 and Sixel use cells when an in-plot legend would overlap the image; text-free plots can use native images. Automatic rasters are limited to 4096 pixels per side, one million pixels each, four million accepted pixels per frame, 65,536 points, and 32 million estimated primitive-pixel operations. The presenter retains exact decoded pixels by accepted render order and avoids re-uploading unchanged content; the chart still rasterizes each invocation.

`BarChart` is behind the `barchart` feature. It draws bars from `Bar` values, alone or in labeled `BarGroup`s, vertical or horizontal, with eighth-block ends, bar width, bar gap and group gap, labels, and value text. Without a style the bars take theme tokens for the current `WidgetState`.

The default `pixel-barchart` feature draws antialiased fills at native pixel precision through a measured image presenter. Existing constructors use pixels automatically; `.pixels(false)` keeps the original eighth-block renderer. Labels and value text remain terminal text, including spaces and wide characters. Bar backgrounds keep their original cell coverage, and DIM affects only the native foreground. Kitty supports text over the image; iTerm2 and Sixel use cells when text overlaps it. Missing metrics, unresolved colors, unsupported attributes, excessive work, and declined rasters also reproduce the complete cell result. Native targets are limited to 4096 pixels per side, one million pixels, 65,536 source items, one MiB of source text, and 32 million estimated work units. The `pixel_bar_chart` example shares the preview's grouped requests, regional latency, build runs, and queue states in equal-size Cells and Pixels panes.

`MarkdownView` is behind the `markdown` feature. It lays a parsed `lunatui_text::markdown::Document` out at the width it is given and draws headings, wrapped paragraphs with emphasis, code, and links, lists with task markers, block quotes, code blocks, tables, and rules. `scroll` moves it by rows and `content_height` sizes a scrollbar; every cell of the area is rewritten, and `background` keeps a panel color.

`Breadcrumbs` draws a one-row path. A path wider than the area collapses its middle to `…`, keeping the first segment and as many of the last as fit, and `segment_areas` gives each shown segment's cells for `HitMap` hit testing.

`SplitTree` holds nested splits: each divides its area between two panes or further splits at a ratio (in thousandths) with optional minimum sizes, and one pane can be zoomed to fill everything. `layout` returns each pane's cells and each divider's one-cell line for drawing and hit testing, `SplitDrag` turns pointer press, drag, and release on a divider into cell-exact resizing that stops at the minimums (and can cancel), and `SplitLayout::render_dividers` draws the lines.

`Canvas` is behind the `canvas` feature. It is a free-form drawing surface: a paint closure draws `canvas::Line`, `Rectangle`, `Circle`, and `Points` shapes (or its own `Shape`) in coordinates of your choosing, starts new layers with `Context::layer`, and prints labels with `Context::print`. Lines use braille's 2×4 sub-cell grid by default for fine detail; `Context::marker` switches individual shapes to another marker, such as half blocks or blocks for filled regions. Other markers are sextant, quadrant, and dot. Shapes are clipped to the bounds, every cell of the area is rewritten, and a `background` keeps a panel color.

The default `pixel-canvas` feature enables antialiased native geometry when a measured image presenter is attached. `.pixels(false)` selects the original cell renderer. The paint callback and custom shapes run once per render, including when pixels are rejected; `Painter::resolution` keeps its cell/marker meaning. Native lines and circles use continuous outlines, while block and subcell point markers retain filled pixel footprints. Native layers blend covered pixels in order; explicit cell mode retains whole-cell layer replacement.

Labels remain real terminal text, with their complete visible spans clearing the image behind them, including spaces and wide characters. Kitty supports this text underlay. iTerm2 and Sixel retain cells for visible labels; the six label-rich showcase scenes therefore use native images on Kitty. Unsupported primitive styles, reversed cell backgrounds, missing metrics, rejected requests, and excessive work use the same cell result. Native targets are limited to 4096 pixels per side, one million pixels, 65,536 recorded operations, and 32 million estimated work units. The `pixel_canvas` example preserves equal-size, same-tick Braille and pixel views of Scope, Globe, System, Clock/tree, Flock, and Pings.

`Toggle` is behind the `toggle` feature. It draws an on/off switch (`━━━●` on, `●───` off) with an optional label, a configurable track width, and the widget states: focused uses the focus-ring knob and a bold label, disabled dims it. `Toggle::hit_area` gives the cells a click should reach, so it plugs into `HitMap`.

`RadioGroup` is behind the `radio` feature. It draws a group of options of which at most one is selected (`◉` and `○`), one per row or side by side with a gap, with the focused option in the focus ring color with a bold label, per-option and whole-group disabling, and `option_areas` for hit testing. `RadioGroup::step` moves the selection with the keyboard, wrapping around and skipping disabled options.

`Form` is behind the `form` feature. It lays out labelled fields (a label column, an input area for your own widget, and a message row) and draws the labels, `*` markers for required fields, dim hints, and fail-colored validation messages. `FormField` sets a label, required, disabled, hint, error, and input height; `Form::layout` returns each part's cells for drawing inputs and for hit testing; `Form::step` moves focus in tab order, wrapping and skipping disabled fields; and `check_required` fills "Required" for empty required fields.

`Tooltip` is behind the `tooltip` feature. It draws a short hint beside an anchor rectangle and never covers it: it opens on its side (below by default), flips to the opposite side and then to the other two when there is no room, slides along the side to stay inside the area, and is not drawn when no side fits. The text wraps at spaces to `max_width`, padding included, and the tooltip is as wide as its widest row; rendering does not allocate. `Tooltip::area` gives the covered cells for `HitMap`. `TooltipState` shows it after the pointer rests on the anchor for a delay (half a second by default), hides it when the pointer leaves, and `dismiss` hides it until the pointer comes back, with time passed in by the caller.

`PieChart` is behind the `pie-chart` feature. It draws a pie or donut of labelled slices with a legend. `HalfBlock` (the default), `Quadrant`, and `Sextant` markers fill each cell with up to two slice colors, and `Braille` draws the disc as dots. A `reveal` fraction sweeps the slices in over a `surface.1` track, `highlight` pulls one slice out, `donut` cuts a hole for `center` text and a `caption`, and `cell_aspect` keeps the disc round. `layout` gives the disc and legend rectangles, `slice_at` maps a cell to its slice, and `percents` rounds the shares so they add up to 100.

`PixelPieChart` is behind the default `pixel-pie-chart` feature, with tiny-skia as a pure Rust rasterizer. Use `.pixels(false)` for an explicit Braille-only instance. The original `PieChart` remains available for Braille/text versions and mirrored comparisons. Wrap a `PieChart` and give it a unique `ImageId`: `PixelPieChart::new(id, chart)`. Attach the runtime frame's image sink to `RenderCx` with the default `image-presenter`. The wrapper owns the raster cache and revisions; `set_chart` updates the specification and `chart()` exposes layout and hit testing.

Pixels require a positively reported protocol and measured cell dimensions. Kitty, iTerm2 inline PNG, and Sixel share the image presenter. Missing metrics, unknown support, tmux, screen, rejected requests, and resource limits select Braille. iTerm2 and Sixel also use Braille for center/caption text or existing text inside the image rectangle. Compose other widgets beside those images: they have no independent text-underlay layer. The raster preserves resolved cell backgrounds; an unresolved terminal-default background also selects Braille. Rasters are limited to one million pixels, 4096 pixels per side, and 32 million slice-pixel samples. Generation exhaustion retains Braille rather than reusing an old revision.


`HexViewer` is behind the `hex-viewer` feature. It shows a byte slice as offset, hex, and ASCII columns, drawing only the visible rows, with a vertical scrollbar when the rows do not fit. `HexViewerState` keeps the cursor, the selection, and the scroll position: moves by byte, row, page, row start and end, and file start and end can extend the selection, and `scroll_up`/`scroll_down` move the view without the cursor. `HexViewer::sync` records the sizes the moves need, `byte_at` maps a mouse cell to a byte in either column, and `fitting_bytes_per_row` picks the widest row for a width.
`ProgressBar` is behind the `progress` feature. It draws a bar of eighth blocks in three modes: one `ratio` segment, stacked `segment`s in accent, ok, warn, or fail (a cell where two segments meet shows both colors), or an `indeterminate` block that bounces along the track a tick at a time. A label can go before the bar and the percentage after it, the bar fills every row of its area, and `percent` and `track_area` report the numbers and cells.

`Accordion` is behind the `accordion` feature. It stacks collapsible sections: each header has a caret, a title, and a dim badge on the right, and each open section gets a body area for the caller's own content. `layout` gives every header and body rectangle (for drawing and hit testing), a section's `reveal` fraction sets how many body rows show so an open or close can animate, and `step` moves focus through the headers in tab order, wrapping and skipping disabled sections.
`NumberInput` is behind the `number-input` feature. It draws a spin box: a value right-aligned between a minus and a plus button, with an optional prefix and suffix, and the text being typed with a caret while the app is editing. The app owns the value and the text; `nudge` steps the value by whole steps (rounded to the decimals and clamped to the range), `accepts` and `parse` validate typed text, `format` shows a value, and `minus_area`, `plus_area`, and `field_area` give the cells to hit test.

`Slider` is behind the `slider` feature. It draws a one-row slider for a single value or a range, with the filled part of the track ending on a half cell (`━━╸───`), an optional `●` knob on each end, a label, and the value (or `low–high`) after the track. `value_at` turns a click or drag column into a value snapped to the step, `nudge` moves a value by whole steps for the keyboard, and `track_area` and `thumb_areas` give the cells for hit testing.

`DiffView` is behind the `diff-view` feature. `Diff::parse` reads unified diff text (from `diff -u` or `git diff` for one file) into hunks of context, added, and removed lines with old and new line numbers, and `DiffView` draws it with hunk headers, line numbers, and added and removed lines in the ok and fail colors. The unified layout lists removed lines and then added lines; the side-by-side layout pairs a run of removed lines with the added lines that follow it and leaves the shorter side blank. The text between the common start and end of each paired removed and added line is drawn inverted. `scroll` sets the first row, and `rows` and `max_scroll` give an app the numbers for a scrollbar.

`LogView` is behind the `log-view` feature. The app fills a `LogBuffer`, a ring buffer of `LogEntry` values (level, target, message, and an optional time label) that drops the oldest entry when it is full, and the view draws the newest rows with a level-colored label, a dim target column, and the message. It filters by minimum `LogLevel`, target prefix, and a smart-case text query that highlights the match, follows the newest entry by default, and with `follow(false)` and `scroll` leaves a number of matching entries out below the view. `matching` and `max_scroll` report the counts for a scrollbar, and `LogBuffer::counts` gives the totals per level.

`NotificationCenter` is behind the `notification-center` feature, which also turns on `toast`. The app keeps a `NotificationLog`, a ring buffer that drops the oldest entry when full, and pushes an entry (kind, message, and a time label it formats) next to each `Toast` it shows, so the message outlives the toast. The widget lists the entries newest first under a header that counts the unread ones ("All read" when none are). Each row has a mark that is filled while unread, a dim time label, the message (bold while unread, dim once read), and a `×` to dismiss it; the mark takes the color of the entry's `ToastKind`. The app owns which row is selected, counted from the newest, and the list scrolls to keep it in view. `NotificationLog` has `dismiss`, `clear`, `mark_read`, `mark_all_read`, and `unread`, and `row_at` and `dismiss_at` give the cells to hit test. Drawing allocates nothing.

`DatePicker` is behind the `date-picker` feature, which also turns on `calendar`. It draws a month grid, always 21 columns by 8 rows so the layout does not jump between months: a header with previous and next arrows, a weekday row, and the days in cells three columns wide. The app owns the cursor (which also picks the month shown), the selection (one date from `selected`, or two ends from `range`, given in either order), the optional `min` and `max` bounds, and an optional `today`. A chosen day or the ends of a range are filled with the accent color and the days between sit on a band; days outside the bounds are dimmed; focused underlines the cursor day. `shift_days`, `shift_months` (a day the new month lacks becomes its last day), and `clamped` move a cursor for arrow and page keys, and `prev_area`, `next_area`, and `date_at` give the cells to hit test.

`ComboBox` is behind the `combo-box` feature, which also turns on `search-box`. It draws a one-row text field with a down arrow and, while `open`, a drop-down list of the options that match what was typed, below the field and over whatever is there. The app owns the text, the caret, whether the list is open, and the active row; matching is `SearchBox::filter` (smart case, every space-separated term), with the matched part of each option highlighted. `matches` returns the filtered options so the app can map the active row back to an option, and `SearchBox::step` moves through them. The list shows at most `max_rows` rows (six by default), scrolls to keep the active row in view, and says "No matches" when nothing fits. `field_area`, `list_area`, and `option_at` give the cells to hit test.

`SearchBox` is behind the `search-box` feature. It draws a one-row search field: a prompt, the query (or a dim placeholder while it is empty), a match count on the right ("No matches" in the fail color), and a clear button once there is text. The app owns the query and the caret; `SearchBox::filter` applies a query to a list of items (every space-separated term must match, ignoring ASCII case unless a term has an uppercase letter) and returns each match with the byte ranges to highlight, `SearchBox::step` moves through the matches with wrap-around, `SearchBox::put_highlighted` draws a row with its ranges marked, and `clear_area` and `query_area` give the cells to hit test.

`Popover` is behind the `popover` feature, which turns on `popup`. It opens a titled, bordered panel beside an anchor rectangle, using the same placement as `Tooltip`: it never covers the anchor, flips and slides to stay inside the area, and is not drawn when no side has room or the area leaves no cell inside the border. It looks like a `Popup` but has no backdrop and does not trap focus. `Popover::area` gives the panel's cells for `HitMap`. `PopoverState::click` toggles the popover from its anchor, keeps it open for clicks inside, and closes it for clicks anywhere else; `close` handles Escape. An untitled popover places and draws without allocating.

`CodeView` is behind the `code-view` feature. It borrows a slice of lines (`&[&str]`, `&[String]`, or anything that is `AsRef<str>`) and draws one per row from the top line, cut at the right edge, with tabs moved to the next `tab_width` stop. The gutter holds a column of `CodeMark` signs when any are given, the line numbers right-aligned and dimmed (numbered from `first_line_number`), and a blank column. The cursor line is drawn on `surface.1` with its number bold in `accent`, or `focus.ring` when focused. A vertical `Scrollbar` takes the right column when the lines overflow. A `CodeHighlight` is called for each visible line and paints byte ranges with styles laid over the line's; a color left as `Color::Default` keeps the line's. `CodeView::sync` gives `CodeViewState` the line count and visible rows so its moves keep the cursor on screen, and `line_at` and `text_area` support hit testing. A built view draws without allocating.

`Button` is behind the `button` feature. It fills the area it is given and centres its label on the middle row, cut to fit when the area is narrow. It measures as the label plus `padding` cells on each side (two by default), one row high. Colors come from theme tokens: `Normal` and `Destructive` buttons rest on `surface.1` with `text.primary` or `fail` text, and `Primary` is filled with `accent`. A focused button is filled with `focus.ring` (`fail` when destructive), a `pressed` one sinks to `surface.0` with its color as text, and a disabled one is dimmed whatever its variant. `style` replaces the theme. `hit_area` gives the cells a click should reach and is empty for a disabled button. `ButtonState` holds whether the button is down: `press` and `release` for Enter or Space, `pointer_down` and `pointer_up` for the pointer, which clicks only when released on the same button, and `cancel` for Escape. A built button draws without allocating.

`Dialog` is behind the `dialog` feature, which turns on `popup`. `Dialog::alert`, `Dialog::confirm`, and `Dialog::prompt` draw a modal dialog as a centred `Popup`: the screen behind fades, the message wraps inside the panel, a prompt adds a one-line field showing the app's text and caret, and the buttons sit right-aligned on the bottom row with confirm last. The focused control is drawn in `focus.ring`, and `destructive(true)` draws the confirm button in `fail`. `DialogState` holds whether a dialog is open and which control has focus: `open` takes the focus id to give back, `next` and `previous` cycle only through the dialog's own controls, and `activate`, `cancel`, and `click` close it and return the outcome with that id. `focus_trap` gives the runtime an active `FocusTrap` while a dialog is open. `area` and `control_at` support hit testing, and a built dialog draws without allocating.

`ToastStack` is behind the `toast` feature. It holds timed messages and takes the time from the caller (a `Duration`, such as a virtual clock's `now`), so expiry is deterministic. A toast is scoped to a pane (a boxed message in the pane's bottom-right corner, newest nearest the corner) or to the status rows (one line each, right aligned). `placements` returns each shown toast's cells and layer for `HitMap`, and `render` draws them with theme colors for the kind.

`Sparkline` is behind the `sparkline` feature. It draws one column per sample with the eight block steps, matches ratatui when given an explicit style, and otherwise paints from theme tokens for the current `WidgetState`.

The default `pixel-sparkline` feature adds antialiased fills at native pixel precision. `.pixels(false)` retains the original cell path. Row colors, per-sample styles, the minimum baseline, direction and missing samples keep their existing meaning. `NINE_LEVELS` uses raw-value geometry; coarser and custom block glyphs retain their rendered row shapes. Unsupported rendered glyphs, attributes, unresolved colors, missing metrics and declined rasters leave the complete original cell result. Native RGB fills support focused bold and DIM; DIM halves the foreground only. Palette-dependent bold uses cells.

Sparkline preserves both sample-reading passes and their order, including a callback panic's partial cell output. It finishes all sample callbacks before querying the image sink, reads final cell styles, and removes only verified generated ink after image acceptance. Unused columns and block borders stay outside the image. No image sink or `.pixels(false)` adds no recording allocation; an attached unsupported sink may allocate a bounded column record before support is known. Native targets are limited to 4096 pixels per side, one million pixels, 65,536 logical cells and 32 million estimated work units. The `pixel_sparkline` example shares the service-board scenes with equal-size Cells/Pixels views, including all ten lanes and the selected inspector.

`Popup` is behind the `popup` feature. It draws a titled, bordered panel over an `Overlay` backdrop, centred, at a point, or anchored beside a rectangle, and `PopupState` tracks dragging and moving. Content cells drawn without colors take the panel's.

`ScrollView` is behind the `scroll-view` feature. It draws a widget into an offscreen grid of the content size and copies the visible part, with automatic, always, or hidden scrollbars on each axis. `ScrollViewState` keeps the offset and pages once `ScrollView::sync` has recorded the sizes.

`SpinnerPreset` is a catalog of named cycles on the existing `Spinner`: dots, line, arc, bounce, pulse, moon, ring, bars, quadrant, and half-moon. Each preset has its own frames and the interval between them. `Spinner::preset` selects one. The default spinner still draws Braille dots, and the caller still supplies the frame index.

`Image`, `ImageSource`, and `ImageFit` are behind the `image` feature. `ImageSource::rgba8` accepts validated immutable RGBA8 data; `ImageSource::decode` is also available with `image-decode`, for PNG, JPEG, GIF, and WebP. The widget draws a half-block fallback with alpha composited over the `surface.0` theme token. A focused image gets a rounded `focus.ring` border; a disabled image is dimmed over the surface. `ImageFit::Contain`, `Cover`, `Stretch`, and `Native` share pixel-space geometry from `lunatui-image`. To use the default runtime image presenter, override `App::render_frame` and pass its image sink to `RenderCx::image_sink`. Give each image a stable nonzero `ImageId`; increment its generation whenever source pixels change. Kitty, iTerm2 inline PNG, and Sixel are selected from positive capability reports; unsupported paths retain half blocks. Prismattyc-native presentation remains separate.

`Lightcycle::new(elapsed)` draws an eight-way Braille sub-cell trail for the supplied elapsed time. It does not own a clock; the application supplies each frame's time and schedules redraws.

`Menu`, `MenuItem`, `MenuState`, and `MenuEvent` are behind the opt-in `nested-menu` feature. Build a recursive item tree, keep `MenuState` in the application, forward key presses to its navigation methods, and drain selected actions after rendering:

```rust
# #[cfg(feature = "nested-menu")]
# {
use lunatui_widgets::{MenuEvent, MenuItem, MenuState};

let mut state = MenuState::new(vec![
    MenuItem::group("File", vec![
        MenuItem::item("Open", "open"),
        MenuItem::group("Recent", vec![
            MenuItem::item("notes.txt", "open-recent"),
        ]),
    ]),
]);

state.activate();
state.down();
state.down();
state.right();
state.select();
assert_eq!(
    state.drain_events().collect::<Vec<_>>(),
    [MenuEvent::Selected("open-recent")],
);
# }
```

Render with `Menu::new(&state)` and provide a `WidgetState` for token-based styling. The feature enables Graphite token support; applications choose their own key bindings and event loop.

`Table` sorts, selects ranges and resizes columns through `TableState`. `sort` orders the rows by one column's text, comparing numbers by value and other text without regard to case, and keeps the cursor on the same source row; draw with `Table::new(state.view(&source), columns).state(&state)`, which shows the rows in that order and applies the cursor, the selected range (`selection_style`), a `▲` or `▼` marker after the sorted column's title, and column widths set with `set_column_width` or a divider drag (`start_resize`, `drag_resize`, `end_resize` with `Table::divider_at`). `Table::column_at` finds a clicked column, `Table::sync` or `data_rows` with `TableState::fit` keeps the cursor on screen, and a closure `Fn(row, column) -> Style` styles single cells. Over a source that answers `RowSource::cell`, as `VecSource` and `SliceSource` do, a built table draws without allocating.

Snapshot tests use `lunatui_test::styled_snapshot`. See [Getting started](../docs/getting-started.md).
