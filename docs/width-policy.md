# Width policy

How lunatui decides how many terminal columns a character takes (PRD §2.1, §2.5 and §8 PR 04). `lunatui_core::char_width` and `lunatui_core::width` implement it. Its tables come from **Unicode 18.0.0** and are generated by `cargo xtask gen-width` into `lunatui-core/src/width/tables.rs`.

## Rules

Every code point starts at 1 column. The rules below apply in order, and a later rule overrides an earlier one.

| Order | Code points | Width | Source |
|---|---|---|---|
| 1 | Everything | 1 | default |
| 2 | `Default_Ignorable_Code_Point` (ZWJ, ZWNJ, variation selectors, zero-width space, tags, …) | 0 | `DerivedCoreProperties.txt` |
| 3 | East Asian Width `W` (wide) or `F` (fullwidth) | 2 | `EastAsianWidth.txt` |
| 4 | `Emoji_Presentation` | 2 | `emoji/emoji-data.txt` |
| 5 | General category `Mn` (nonspacing mark) or `Me` (enclosing mark) | 0 | `extracted/DerivedGeneralCategory.txt` |
| 6 | Hangul jamo `V` (medial vowel) or `T` (final consonant) | 0 | `HangulSyllableType.txt` |
| 7 | C0 and C1 controls and DEL (U+0000–001F, U+007F–009F) | 0 | fixed |
| 8 | U+00AD SOFT HYPHEN | 1 | fixed |

Why this order:
- **Wide beats default-ignorable (3 after 2).** U+3164 HANGUL FILLER is both, and terminals draw it as a wide blank.
- **Marks beat wide (5 after 3).** Combining marks that are East Asian Wide, such as the ideographic tone marks U+302A–302D, attach to the previous character and take no column.
- **Controls take no column (7).** They are never stored in a cell; the grid write APIs handle them.
- **Soft hyphen is 1 (8).** Terminals and glibc `wcwidth` draw it as a visible hyphen, although Unicode marks it default-ignorable.

East Asian Width `A` (ambiguous) is **narrow**, the Unicode default. Per-terminal overrides, such as treating ambiguous characters as wide in CJK locales, are part of the terminal width policy (§2.5) and come later.

`width(text)` is the sum of `char_width` over the characters of `text`, with a fast path for ASCII.

## Grapheme clusters (PR 05)

`width` and `lunatui_core::text_display_width` segment with Unicode extended grapheme rules, then measure each cluster with `cluster_display_width`. ZWJ emoji, VS16 sequences and regional-indicator flags take the width terminals usually draw:

| Text | `width` |
|---|---|
| `👩‍💻` (woman, ZWJ, laptop) | 2 |
| `❤️` (heart, VS16) | 2 |
| `🇺🇸` (two regional indicators) | 2 |

Terminals that report DEC mode 2027 segment clusters the same way (§2.1). Per-terminal overrides for ambiguous width still follow §2.5.

## Differences from `unicode-width` 0.2.2

`lunatui-core/tests/width_vs_unicode_width.rs` compares every code point with the `unicode-width` crate, version 0.2.2, which uses Unicode 17.0.0. It fails on any difference not listed in its named groups, and on any listed difference that disappears. There are 1,200 differing code points in 8 groups:

| Group in the test | Code points | lunatui | `unicode-width` | Why |
|---|---|---|---|---|
| `CONTROLS` | 65: U+0000–001F, U+007F–009F | 0 | none (`None`) | Rule 7. `unicode-width` gives controls no width at all; a cell grid needs a number, and controls never occupy a cell. |
| `SOFT_HYPHEN` | U+00AD | 1 | 0 | Rule 8, matching terminals and `wcwidth`. |
| `HANGUL_FILLER` | U+3164 | 2 | 0 | Rule 3 over rule 2: East Asian Wide, drawn as a wide blank. |
| `REGIONAL_INDICATORS` | 26: U+1F1E6–1F1FF | 2 | 1 | Rule 4: they have `Emoji_Presentation`. `unicode-width` measures one indicator as 1 and a flag pair as 2 in its string width. lunatui measures pairs as clusters in PR 05. |
| `PREPENDED_CHARACTERS` | 19 in 12 runs, e.g. U+0605, U+070F, U+0890–0891, U+08E2, U+0D4E, U+111C2–111C3, U+11A84–11A89 | 1 | 0 | `Grapheme_Cluster_Break=Prepend` characters, including the prepended concatenation marks. They are visible and not combining marks, so they keep the default width. `unicode-width` folds them into the following character. |
| `SPACING_GRAPHEME_EXTENDERS` | 63 in 47 runs, e.g. U+09BE, U+0B3E, U+0BBE, U+0CC2, U+0D3E, U+1B35, U+FF9E–FF9F, U+1D165–1D166 | 1, or 2 for U+302E–302F and U+16FF0–16FF1 (East Asian Wide) | 0 | `Grapheme_Extend` characters that are spacing marks (`Mc`) or letters, not `Mn`/`Me`. Rule 5 zeroes only nonspacing and enclosing marks, as `wcwidth` does. These take a column when drawn alone; inside a cluster, PR 05 measures the whole cluster. |
| `UNICODE_WIDTH_SPECIAL_CASES` | U+17A4, U+17D8, U+2D7F, U+A8FA | 1, 1, 0, 1 | 2, 3, 1, 0 | `unicode-width` gives these four code points widths that its general rules don't explain: the deprecated Khmer characters U+17A4 and U+17D8, the Tifinagh consonant joiner and the Devanagari caret. lunatui applies its rules unchanged: U+2D7F is `Mn` (0), and the other three keep the default (1). |
| `NEW_IN_UNICODE_18` | 1,021 in 23 runs, e.g. the Jurchen script U+18E00–19191, U+1F6D9, U+1FA8B–1FA8D, new combining marks U+05C8–05C9, U+1AEC–1AF0 | 0 or 2 by the rules | 1 | Assigned in Unicode 18.0, which `unicode-width` 0.2.2 (Unicode 17.0) treats as unassigned. |

## Regenerating the tables

```sh
cargo xtask gen-width
```

The generator downloads the five UCD files listed above for Unicode 18.0.0 into `target/ucd/18.0.0/` (using `curl`) and rewrites `lunatui-core/src/width/tables.rs`. Moving to a new Unicode version is a change to `xtask/` (MB2090 sign-off). The differential test will then report the differences the new version introduces, and this document is updated in the same PR.
